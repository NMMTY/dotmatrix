Four independent axes, each a `data-*` attribute on `<html>`: `data-theme` (`dark`/`light`),
`data-palette` (accent color), `data-border` (`rounded`/`notched`/`square`), `data-density`
(`compact`/`normal`/`comfortable`). Switching any of them is an attribute write, not a re-render —
no component in the tree needs to know `ThemeProvider` exists to pick up a change.

## Palettes

`mono` (the default) keeps every accent-driven token equal to the gray ramp. Five chromatic hues —
`orange`, `blue`, `green`, `purple`, `red` — each come in three variations: the base vivid tone, a
deeper `-dark`, and a pastel `-light`. Plus `custom`, which derives its whole ramp from a single
colour you supply — 17 values in total.

## Custom palette

Set one seed colour and the accent ramp follows: `100`/`300` are the seed mixed over black (20% and
55%), `500` is the seed itself, `700`/`900` mix it toward white (30% and 70%). Action, hover and
focus colours are derived from the same ramp. Set `--dm-custom-on-seed` to the text/icon colour that
sits on top of it (white or a near-black, whichever keeps contrast), and optionally
`--dm-custom-error`, `--dm-custom-warning` and `--dm-custom-success` to override the status hues.

## Global vs. local

Set a palette globally via `ThemeProvider`/`useTheme`, or scope it to one element's subtree with
the `palette` prop any primitive accepts — the same `data-palette` mechanism, just anchored lower.
Click the button below: it cycles the *global* palette, and every solid `Button`/`Switch`/
`Radio`/`Checkbox` on this page reacts, except the one explicitly pinned to `palette="blue"`.

## What actually changes color

Only key interactive states: a `solid` button's background, a checked `Switch`/`Radio`/
`Checkbox`'s fill, and the focus ring. Everything else — text, borders, surfaces — stays
monochrome regardless of palette, by design.
