Every icon in the design system renders through this one component — `name` looks up the bitmap
in the glyph catalog rather than each icon being its own component. Fixed 18×18 viewBox (a 9×9
bitmap at 2 units a cell), size in three steps — `s` 9px, `m` 18px, `l` 27px, whole multiples of
the grid so the bitmap stays crisp — and fill inherited from `currentColor` so an icon always
matches its surrounding text.
See the [Icons guide](/guides/icons) for the full catalog.

## Examples

Fill always comes from `currentColor`, so pairing an icon with text just means putting both inside
the same colored wrapper — no separate `color` prop on `Icon` itself to keep in sync:

<CodeBlock
  codes={[
    {
      language: "tsx",
      code: '<Text color="strong">\n  <Icon name="warning" size="s" /> Something went wrong\n</Text>',
    },
  ]}
  preview={
    <Text color="strong">
      <Icon name="warning" size="s" /> Something went wrong
    </Text>
  }
/>

Most controls that need an icon (`Button`, `IconButton`, `Input`) take an `IconName` on their own
`icon` prop rather than a rendered `<Icon>` child — reach for `<Icon>` directly only when there's
no such prop to use, e.g. inline in prose or next to plain text.

Need a glyph that isn't in this catalog? See
[ExternalIcon](/components/typography/external-icon) for loading one from react-icons (or any
similarly-shaped icon set) instead.
